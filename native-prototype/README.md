# Hunmeng Native — v0.1 preview

**Это отдельный прототип**, а не обновление существующего приложения с WebView.

## Возможности
- Полностью нативный интерфейс на Kotlin + Jetpack Compose (**нет WebView**).
- Публичный каталог с сайта `https://hunmeng-novel.ru/catalog.json`.
- Поиск по названию и автору, карточка книги и список опубликованных глав.
- Чтение текста главы из `/mobile/chapters/<novel>/<chapter>.json` нативными Android-компонентами.
- Кнопки предыдущей/следующей главы, настройка размера текста.
- Локальная полка «Saved» на устройстве (пока **не** облачная синхронизация).

**Пока не реализованы:** вход в аккаунт, облачная библиотека, XP/ранги, скачивание глав офлайн, push-уведомления. Эти функции нужно переносить отдельно через безопасный пользовательский API; нельзя использовать admin/service-role ключи Supabase в APK. Текущий рендерер Markdown упрощён и не воспроизводит все виды форматирования.

## Почему отдельное приложение
Package ID: `com.hunmeng.novel.nativeapp`. Оно устанавливается **рядом** с текущим WebView `com.hunmeng.novel` и не заменяет его автоматически. Ни подпись, ни механизм обновлений действующей версии не изменены.

## Запуск через Android Studio / Code On The Go
1. Открой папку `native-prototype` как отдельный Gradle-проект (или создай новый Empty Compose Activity и перенеси исходники).
2. JDK 17, Android SDK 35. При наличии Gradle Wrapper корневого репозитория из корня:
   ```bash
   ./gradlew -p native-prototype :app:assembleDebug
   ./gradlew -p native-prototype :app:testDebugUnitTest
   ```
3. Debug APK: `native-prototype/app/build/outputs/apk/debug/app-debug.apk`.

При первом запуске нужен интернет. Если на живом сайте ещё нет маршрута `/mobile/chapters/...`, каталог откроется, но чтение покажет ошибку HTTP 404 до публикации соответствующего API.
